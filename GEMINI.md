# CFB Model Research & Fitting Rules

Rules and conventions for the research repository that differ from the live `travispollard.com/cfb` pipeline. All base rules from `travispollard.com/cfb/CLAUDE.md` (unmapped teams raise, S3 immutability, AWS profile discipline) remain in force.

## 1. Research vs Live Repo

- `../travispollard.com/cfb` is strictly **READ-ONLY**.
- Fitting and evaluation run locally against the mirror at `./research/raw/` with zero network calls and zero quota cost.

## 2. Core Differences & Guardrails

- **Leakage is the primary risk:** Research fails by producing a number you believe. Features for Week $N$ must strictly use data available as of Week $N-1$ (`LeakageError`). Always use walk-forward validation, never random k-fold splits. Keep 2024–2025 strictly held out until hyperparameter search spaces are frozen.
- **CFBD backfill requires `--dry-run`:** Backfill writes directly to immutable S3 (`s3://travispollard-cfb-data/raw/cfbd/`) and spends monthly quota (~510 calls). Always run with `--dry-run` first to verify call budgets before live execution.
- **No notebook numbers in `experiments/`:** Reproducibility is mandatory. Every number in `research/experiments/` must be generated by reproducible CLI commands (`cfb fit ...`), never copied out of ephemeral notebook cells.
- **Failures must be documented:** Negative results are essential findings that prevent repeating bad paths. Record every failed fit or rejected model in `research/README.md` and `experiments/` metadata.

## 3. Standard Commands

```bash
uv sync --extra s3               # Install with S3 / boto3 support
uv run pytest                    # Run tests
uv run ruff check --fix .        # Linting
aws s3 sync s3://travispollard-cfb-data/raw/cfbd/ ./research/raw/cfbd/ --profile tp-site
```
